# 데이터 저장 방식 (Data Storage)

## Decisions

- 여행 데이터(Trip, Day, 일정 항목)와 업로드된 사진은 별도 데이터베이스 없이 서버 로컬 파일 시스템(JSON 파일 + 파일 저장소)에 저장한다.

## Boundaries

- 이 결정은 로컬/단일 서버 배포를 전제로 한다. 서버리스나 컨테이너처럼 파일 시스템이 재시작 시 초기화되는 환경에 배포하면 데이터가 유지되지 않는다.

## Why

DB를 설치·연동하는 과정 없이 "한 번에 구현하고 실제 동작으로 검증"할 수 있는 범위를 유지하기 위함이다. 로컬 JSON 파일은 서버 재시작 후에도 유지되어 실제 add/delete 동작을 검증하기에 충분하다.

## Reconsider when

- 여러 사람이 동시에 쓰기 작업을 자주 해 파일 쓰기 충돌이 관찰되거나, 파일 시스템이 휘발성인 환경(서버리스·컨테이너 등)에 배포해야 하는 시점에 재검토한다.

## Still-rejected alternatives

- SQLite·Postgres 등 실제 DB 도입 — 설치·마이그레이션 등 구현 범위가 커져 보류; 동시 편집 충돌이나 배포 환경 제약이 실제로 드러나면 재검토.
