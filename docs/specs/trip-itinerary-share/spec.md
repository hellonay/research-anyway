# 여행 일정 공유 (trip-itinerary-share)

## 개요

친구들과 함께 가는 해외 여행의 일정·바우처·위치·이동수단 정보를 하나의 웹페이지에서 공유한다. 공유 링크를 아는 사람은 누구나 내용을 보고, 필요할 때 항목을 추가·수정·삭제해 최신 상태로 유지한다. 여행 중에는 주로 휴대폰으로 열어보므로 화면은 모바일 사용을 기준으로 만든다.

## 범위

- 여행(Trip)은 이 앱에서 단 하나만 존재한다. 별도 URL로 접속하면 바로 그 여행 페이지가 보인다. 여행 생성·목록·전환 UI는 없다.
- 화면 최상단에 **일정 · 정보 · 사진** 3개 탭을 두고, 각 탭은 별도 URL(`/`, `/info`, `/photos`)로 이동한다. 탭 바는 화면 위에 고정되어 스크롤해도 계속 보인다.
- 화면과 조작 요소(입력창, 버튼)는 휴대폰 화면 폭을 기준으로 배치하고, 더 넓은 화면에서도 어색하지 않게 확장한다.

### 일정 탭 (`/`)

- Trip은 제목, 여행 기간(시작~종료일), 대표 이미지(선택)를 가지며 언제든 수정할 수 있다.
- Trip 안에 Day를 자유롭게 추가·삭제할 수 있다. Day는 여행 기간과 무관하게 사용자가 직접 관리하며, 라벨은 실제 날짜(예: 2026-09-10)든 자유 텍스트(예: "목요일")든 그대로 입력한 값을 보여준다.
- 각 Day는 접었다 펼 수 있다. 펼치면 그 안의 일정 항목(Item) 목록과 "항목 추가" 입력창이 보인다.
- 각 Day 안에 일정 항목(Item)을 추가·수정·삭제할 수 있다. 항목은 다음 정보를 가진다.
  - 제목(필수)
  - 유형: 항공권 · 숙소 · 골프 · 식당 · 관광 · 이동수단 · 기타
  - 시작 시간(선택), 종료 시간(선택) — 종료 시간은 시작 시간이 있을 때만 의미가 있다.
  - 메모(선택, 텍스트)
  - 사진(선택, 여러 장 업로드 가능 — 비행기 티켓, 호텔·골프 예약 바우처 등도 사진으로 첨부)
  - 구글맵 링크(선택, URL — 호텔·숙소·식당·관광지·공항 등의 위치 공유용)
- 각 일정 항목도 접었다 펼 수 있다. 접힌 상태에서는 유형·시간·제목만 보이는 한 줄이고, 펼치면 메모·사진·구글맵 링크와 수정·삭제 조작이 보인다.
- 항목 수정에서는 제목·유형·시작/종료 시간·메모·구글맵 링크를 고쳐 저장할 수 있고, 사진을 추가로 올리거나 기존 사진 중 하나를 골라 뺄 수 있다.
- Day 안의 항목은 시작 시간 순으로 정렬한다. 시작 시간이 없는 항목은 해당 Day 목록의 맨 뒤에 입력 순서대로 배치한다.
- 항목의 구글맵 링크를 누르면 새 탭에서 구글맵으로 이동한다.

### 정보 탭 (`/info`)

- 참여자가 여행에 필요한 정보를 자유 형식의 "정보 카드" 여러 개로 남길 수 있다. 카드 하나는 제목(선택)·본문 텍스트(선택)·사진(선택, 여러 장)을 가진다.
- 누구나 정보 카드를 추가·수정(제목·본문·사진 추가/제거)·삭제할 수 있다.

### 사진 탭 (`/photos`)

- 참여자가 필요한 사진을 올리고 지울 수 있는 공유 사진첩이다. 사진마다 짧은 설명(선택, 텍스트)을 붙일 수 있다.
- 사진은 그리드로 보여주고, 사진마다 삭제 버튼이 있다.

### 공통

- 데이터(Trip·Day·항목·정보 카드·사진첩 사진)와 업로드된 사진은 배포 환경에 맞는 저장소(로컬 개발은 파일, Vercel 등 서버리스 배포는 DB)에 저장되어, 새로고침·재배포 후에도 유지된다([data-storage 결정](../../decisions/data-storage.md)).
- 로그인 없이 링크를 아는 사람은 모두 열람과 수정(추가·수정·삭제)이 가능하다. 앱 안에 사용자 계정이나 이름 구분은 없다([access-control 결정](../../decisions/access-control.md) 그대로 유지).

## 수용 기준

1. 방문자가 루트 URL로 접속하면 상단에 일정·정보·사진 탭이 보이고, 기본으로 일정 탭(여행 제목과 Day별 일정)이 보인다.
2. 정보·사진 탭을 누르면 해당 화면으로 이동하고, 다시 일정 탭을 누르면 되돌아온다. 탭 바는 스크롤해도 화면에 고정되어 보인다.
3. 모바일 화면 폭(대략 375~430px)에서 글자와 버튼이 잘리거나 겹치지 않고, 버튼을 손가락으로 누르기 불편할 만큼 작지 않다.
4. "Day 추가"로 라벨을 지정해 새 Day를 만들면 화면에 즉시 반영된다.
5. Day를 누르면 접히거나 펼쳐진다. 접힌 Day는 항목 목록이 보이지 않는다.
6. Day 안에서 "항목 추가"로 제목·유형·시작/종료 시간·메모·구글맵 링크를 입력하고 사진을 업로드하면, 저장 후 해당 Day 목록에 새 항목이 나타난다.
7. 항목을 누르면 접히거나 펼쳐진다. 펼친 항목에서 "수정"으로 제목·유형·시간·메모·구글맵 링크를 고치고 사진을 추가하거나 기존 사진을 뺄 수 있으며, 저장하면 목록에 바로 반영된다.
8. 항목에 첨부한 사진이 펼친 상태에서 썸네일로 보인다.
9. 항목의 구글맵 링크를 클릭하면 새 탭에서 구글맵 페이지로 이동한다.
10. Day 안의 항목들은 시작 시간 순으로 정렬되어 보이고, 종료 시간이 있으면 시작~종료가 함께 표시된다.
11. 항목이나 Day를 삭제하면 화면에서 즉시 사라지고, 새로고침해도 다시 나타나지 않는다.
12. 정보 탭에서 정보 카드를 추가(제목/본문/사진)·수정·삭제할 수 있고, 결과가 화면에 즉시 반영된다.
13. 사진 탭에서 사진을 올리고(설명 포함) 삭제할 수 있고, 그리드에 즉시 반영된다.
14. 브라우저를 새로고침하거나 개발 서버를 재시작해도 세 탭의 모든 데이터(일정·정보·사진)가 그대로 남아있다.
15. 같은 URL을 다른 브라우저(또는 시크릿 창)로 열어도 동일한 데이터가 보인다(로그인 없이 공유됨을 확인).

## 결정과 근거

- **접근 권한**: 로그인 없이 공유 링크로 열람+수정. 근거와 재검토 조건은 [access-control 결정](../../decisions/access-control.md) 참고. 정보·사진 탭이 "각 참여자"가 채우는 공간이라도 계정/이름 구분을 새로 두지 않는다 — 이 결정의 범위 그대로다.
- **데이터 저장**: `DATABASE_URL`이 있으면 Postgres, 없으면 로컬 JSON 파일(사진은 base64 또는 `public/uploads`). 근거는 [data-storage 결정](../../decisions/data-storage.md) 참고 — 처음에는 파일만 썼으나 Vercel 배포에서 서버 에러가 나 DB로 재검토했다.
- **일정 구조**: 일정을 Day별로 그룹화해서 보여준다(사용자 확인 완료). 날짜 구분 없는 단일 타임라인은 채택하지 않았다.
- **지도 연동**: Google Maps Embed/JavaScript API를 쓰지 않고, 구글맵 URL만 저장해 클릭 시 새 탭으로 연다. API 키 발급이나 환경변수 설정 없이 바로 동작을 검증할 수 있기 때문이다.
- **탭 구조**: 세 탭을 서로 다른 URL로 구현한다(클라이언트 상태로 전환하는 단일 페이지가 아님). 각 탭을 링크로 바로 공유할 수 있고, 탭 전환에 별도 클라이언트 스크립트가 거의 필요 없다.

## 가정 (뒤집을 수 있음)

- 항목 유형은 항공권·숙소·골프·식당·관광·이동수단·기타 7종으로 고정한다.
- 사진은 항목/정보 카드당 여러 장 첨부할 수 있고, 개수·용량 제한은 두지 않는다.
- 삭제는 별도 확인 다이얼로그 없이 즉시 처리하며 되돌리기는 없다.
- 이미지 파일 형식은 jpg·png·webp·gif 정도로 제한한다.
- Trip 제목·기간·대표 이미지는 최초 진입 시 빈 값 또는 기본값으로 시작하고 이후 언제든 수정할 수 있다.
- "정보"는 하나의 문서가 아니라 여러 개의 독립된 카드(제목+본문+사진) 목록으로 구현한다. 참여자마다 필요한 내용을 각자 카드로 추가하는 방식이 하나의 긴 문서를 여럿이 함께 고치는 것보다 충돌이 적다.
- 사진첩에서 한 번에 여러 장을 올릴 때 설명(캡션)은 그 업로드 묶음 전체에 하나만 붙인다. 사진마다 캡션을 따로 붙이고 싶으면 한 장씩 올린다.
- Day·항목의 접힘/펼침 상태는 새로고침하면 초기 상태(Day는 펼침, 항목은 접힘)로 되돌아간다. 이 상태는 서버에 저장하지 않는다.

## 범위 밖

- 사용자 계정·로그인, 참여자별 권한/작성자 구분 — [access-control 결정](../../decisions/access-control.md)에 따라 이 앱은 인증과 사용자 구분을 두지 않는다. 정보·사진 탭도 "누가 올렸는지"를 기록하지 않는다.
- 여러 여행(트립) 생성·목록·전환 — 이 앱은 여행 1개만 다룬다. 여러 트립이 필요해지면 별도 스펙으로 다룬다.
- 실시간 동시 편집 동기화(웹소켓·폴링) — 다른 사람이 편집한 내용을 보려면 새로고침이 필요하다.
- Google Maps Embed/JavaScript API 연동, 실제 지도 표시 — 링크 이동만 지원한다.
- 사진 전용 오브젝트 스토리지(S3, Vercel Blob 등) 연동 — 사진은 DB 모드에서 base64로, 파일 모드에서 로컬 파일로만 저장한다([data-storage 결정](../../decisions/data-storage.md)).
- 다국어·타임존 처리, 오프라인 지원(PWA), 네이티브 앱 설치(홈 화면 추가 정도는 브라우저 기본 기능에 맡긴다).

## 남는 위험

- 인증이 없어 링크를 아는 누구나 데이터를 삭제·수정할 수 있다. 신뢰할 수 있는 소규모 그룹 공유를 전제로 감수한다.
- 작성자 구분이 없어 정보 카드나 사진을 "누가 올렸는지" 알 수 없다. 참여자가 많아지면 혼란이 생길 수 있지만, 계정 시스템 없이는 해결하지 않기로 한다.
- DB 모드에서는 사진을 base64로 Trip 데이터 안에 통째로 담기 때문에, 사진이 많아지거나 커지면 매 읽기/쓰기가 느려질 수 있다.
- 사진 업로드 용량 제한이 없어 디스크·DB 용량 문제가 생길 수 있다. 학습 템플릿 범위에서는 수용한다.
- `DATABASE_URL`을 설정하지 않고 서버리스 환경에 배포하면 여전히 이전과 같은 서버 에러가 난다.
